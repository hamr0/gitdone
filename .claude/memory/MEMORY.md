## Facts

### Architecture & subsystems
- Email subsystem = three modules with single sources of truth: `email-recipients.js` (`getRecipients(event,edge)→Map<email,role>`, the only recipient resolver, organiser-first — some templates/tests rely on that order), `notifications.js` (`notifyLifecycleEdge`, the only per-event lifecycle dispatcher), `email-bodies.js` (sole catalogue of all transactional subject/body text; must stay acyclic — never requires notifications/email-commands).
- `email-commands.js` is state-machine/computation only, zero email text; its `kind` strings (`pending_started|committed|token_mismatch|pending_remind|already_complete`) are load-bearing and test-asserted — don't rename.
- Deliberate exceptions to the one-body-catalogue rule: verify reports live in `verify.js`/`reverify.js`; invite/setup builders (`notifyWorkflowParticipants`, `notifyDeclarationSigner`, `notifyInitiatorAttachDocsNeeded`) stay outside the lifecycle dispatcher.
- Crypto = two modes (declaration = one signer; attestation = N signers) × three dedup rules (`unique` default, `latest`, `accumulating`); `unique`/`latest` hard-close at threshold, `accumulating` never auto-closes (organiser soft-close only).
- Strict signing toggles on BOTH `reference_url` set AND `reference_docs.length>0` (`isStrictSigningEvent`); either alone = loose. No separate flag. Strict freezes the doc set at first `attach+` email; loose freezes at first counted reply.
- Reference docs arrive via initiator-only DKIM-gated `attach+<id>@`; gitdone hashes (SHA-256 + filename + size) and discards bytes — never stores attachment bytes. Declaration docs go signer-to-signer, never through gitdone.
- Revocation = initiator-only DKIM-gated `revoke+<id>@` (attestation only), permanent by design — no `unrevoke+`. `REVOKE_LINE_RE` is whole-line (email only) to defeat attribution-line spoofing.
- Auth = knowless, one instance: Mode A (magic link IS activation, `bypassRateLimit:true` as trusted server caller) on event/crypto creation; Mode B at `/manage` (respects per-IP limit) for returning organisers.
- Tokens are opaque file-backed (revoke = delete file), not JWT; event data is on-demand walks of `data/events/*.json` — no DB/counter store. Concurrency safety = Postfix `maxproc=1` + in-process `_serialize` mutex (would need FS locking if sharded).

### Gotchas that caused real bugs (check these)
- `event.completion` exists (`{status:'open'}`) from the first counted reply — always test `completion?.status !== 'complete'`, never `!event.completion` (the 4e "completion never flipped" bug).
- Attestor plaintext email is stored only on the bucket-completing strict reply and redacted right after the completion proof email fires; redaction fires ONLY on close-by-initiator inside the dispatcher `closed` edge — never "redact on first proof email" (0.24.x bug). `grep redactAttestorEmails bin/` must stay empty.
- Proof-email re-fire gated by `proof_email_sent_at` (and `completion.completed_at` compare); deliberately NO `${edge}_notified_at` stamp — never strip `proof_email_sent_at` on reopen (breaks revoke-reopen-recomplete re-fire). Proof email is a moment-in-time snapshot; no corrective email to an already-notified attestor.
- Every outbound `buildRawMessage` MUST set `replyTo` to a routable tag (`stepReplyAddr`/`cryptoReplyAddr`); omitting it makes Gmail's Reply hit `gitdone@` and drop silently (launch-day bug).
- `Origin: null` arrives on same-origin form POSTs when `Referrer-Policy: no-referrer` is set — any Origin-based CSRF check must fail-open on null/unparseable; SameSite=Lax is the real backstop.
- `auth.arc.authResults` is a rendered header STRING not an array — read `auth.arc.i` for chain depth; verify mailauth field types before `.length`.
- `receive.js` writes exactly ONE main JSON record to stdout (integration-test contract); rejection paths add a separate `participant_auto_reply` line — tests must split lines, not `JSON.parse(stdout.trim())`.
- Durable vs volatile signals: use `threshold_reached_at` and `completion.closed_by==='initiator'`/`isClosedByInitiator()` (stable) — `completion.reopened_at` is overwritten by `executeClose`.
- Resolve body-email→sender_hash INSIDE `updateEventAtomic` (against `current.salt`), never outside (race).

### Conventions
- Every gitdone email subject: `[gitdone]` prefix, quoted title, `[N/M]` workflow progress (dropped for crypto), em-dash clauses; proof subject `[gitdone] proof — "<title>"` pins the em-dash (tests check it).
- `gitdone` is lowercase everywhere user-facing; brand/customer name is "signed/reply" (amber-slash wordmark); internal names stay "gitdone" (env, units, `/opt` paths, verify CLI, repo, `X-GitDone-*` headers stay PascalCase).
- "Silence is a bug": every accepted/rejected reply gets exactly one threaded auto-reply; every multi-person transition emails all affected.
- Never auto-complete/auto-close: sweep may set/clear `archived_at` (reversible); `event.completion` is a permanent commit — humans decide.
- Status taxonomy (in `summariseEvent()`): `completed` (green) vs `closed early` (amber) vs `archived` (grey, 45d idle) vs `pending activation` vs `open`. Sweep (hourly): 72h pending GC (+24h nudge), 14d overdue nudge (persist `nudged_overdue_at` BEFORE send), 45d archive.
- Editing: step `name`/`depends_on` are NOT editable; an edit writes an `event_edit` commit with salted before/after hashes, never plaintext. `renderWorkflowForm` takes optional `event` and applies locks (no separate edit form).
- knowless caps: subject 60-char ASCII, body 2048-char ASCII / no CR / URL once on its own line; user strings must pass `asciiSafe()`. `bodyOverride` gets `bodyFooter` appended — never also call `withSignature()` (double sig). gitdone's own outbound ships raw UTF-8 (em-dash/middle-dot fine; `sanitizeSubject` does NOT RFC2047-encode).

- Lesson: a convenience shortcut skipping the email round-trip silently reopens the hole the gate exists to close — keep the server-side check even when the UI hides the button.

### 2026-05-02 - knowless integration replaces homegrown auth
- Unified two parallel auth/proof systems; initially bolted knowless on top before realizing Mode A already does do-the-thing-then-confirm. Ended at a single `auth.startLogin` call; removed 6 files, −733 lines, all green.
- Lesson: read knowless GUIDE "Two adoption modes" before touching auth — a parallel email-confirmation token store is almost always Mode A.

### 2026-05-03 - Edit-form positional-array misalignment
- Emitted hidden `step_id` for all steps but inputs only for open steps; index-zip matched a completed step's id against the next open step's value, tripping the frozen guard. Fixed by rendering completed steps fully read-only (no hidden id) and reusing `renderWorkflowForm` with locks.
- Lesson: when zipping parallel hidden/visible arrays, emit them for the exact same rows or not at all — surface the original design with locks, not a divergent second view.

### 2026-05-12 - Strict-signing design (crypto)

- Lesson: strict vs loose diverges in many places (freeze timing, count semantics, ack branches) — "is this signed" must branch on mode (`signed_at` is declaration-only; attestation uses `attestor_progress`).
